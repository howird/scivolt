## Background

### Problem

- controlling high-DOF humanoids in physics simulation settings is difficult due to small deviations leading to falling and tripping
- this is problem is exacerbated by noisy pose inputs generated by video pose estimation OR language models

### Goal

- Create a physics-based humanoid controller that achieves high-fidelity motion imitation and fault-tolerant behavior
- It must be robust to:
    - __noisy input__ (e.g. pose estimates from video or generated from language)
    - __unexpected falls__ (built in recovery)

- Given a reference motion, can __perpetually__ control simulated avatars
    - DOES NOT use external stabilizing forces
    - learns to naturally recover from fail-state (NO RESETS NEEDED)

- Achieve scalability:
    - Train using extensive datasets like AMASS with thousands of motion clips.
    - Avoid catastrophic forgetting when learning diverse motion sequences.

### Key Contributions

- **Progressive Multiplicative Control Policy (PMCP):**
    - Dynamically adds network capacity to handle increasingly challenging motion sequences.
    - Avoids catastrophic forgetting, enabling scalability to large datasets.
- **Adversarial Motion Prior (AMP):**
    - Ensures naturalistic fail-state recovery and smooth transitions back to reference motion.
    - Prevents unnatural artifacts like jittering and "puppeted" motion.
- **Fail-State Recovery:**
    - Addresses limitations of prior methods that reset humanoids after falls, leading to discontinuities in motion.
    - Allows the humanoid to naturally recover from complex fail conditions (e.g., combined falling and displacement).
- **Real-Time Avatar Integration:**
    - Demonstrates robust real-time performance using off-the-shelf pose estimators (e.g., HybrIK, MeTRAbs).
    - Supports video-driven and language-driven motion input for simulated avatars.
### Past Work

- cannot scale to entire dataset
    - using __larger__ or __mixture of expert__ policies
- resorted to using __external forces__ to stabilize the humanoid
    - residual force control (RFC) has helped to create motion imitators that can mimic up to 97% of the AMASS dataset
    - external stabilizing forces are not only unrealistic, but also cause avatars to float/fly
- resort to resetting when failure condition triggered:
    - due to not being robust to noise from video-generated pose estimates
          - which contain: floating, foot sliding, physically impossible poses

## Methodology

![Goal-conditioned RL framework with Adversarial Motion Prior.](2_concepts/media/Pasted%20image%2020241028122215.png)

- Perpetual Humanoid Controller (PHC): a __single__ policy that:
    - achieves a high success rate on motion imitation
    - can recover from fail-state naturally

### RL Formulation

- MDP $\mathcal{M = (S, A, T, {\bf R},} \gamma)$

- state: $s_t \in \mathcal S$, $s_t = (s_t^p, s_t^g)$
    - $s_t^p$: proprioception
    - $s_t^g$: goal state

- transition dynamics, $\mathcal T$, is the simulator which gives $s_{t+1}$
- policy $\pi_\text{PHC}$ computes per step action $a_t\in \mathcal A$
- 
    
- progressive multiplicative control policy (PMCP)
    - which dynamically allocates new network capacity to learn harder and harder motion sequences
    - allows efficient scaling for learning from large-scale motion databases and adding new tasks, such as fail-state recovery, without catastrophic forgetting
- With the target joint set as $q^d_t=a_t$, the torque applied at each joint is $\tau_i = k^p \circ (a_t − q_t) − k^d \circ \dot{q}_t$

#### 1. Goal-Conditioned Motion Imitation
- **Objective:** Design a humanoid controller to mimic reference motions (e.g., joint rotations, keypoints) while maintaining physical realism.

- **Framework Components:**
    - **State:** Composed of humanoid proprioception and goal state.
    - **Action:** Target joint rotations applied using a PD (Proportional-Derivative) controller.
    - **Reward:**
        - Task Reward (e.g., imitation fidelity).
        - Style Reward (via AMP to enforce natural motions).
        - Energy Penalty (to avoid jitter and unphysical behavior).

- **Adversarial Motion Prior (AMP):** A discriminator-based reward to ensure motions appear human-like, especially critical for fail-state recovery.

#### 2. Progressive Multiplicative Control Policy (PMCP)

- **Objective:** Incrementally learn progressively harder motion sequences to avoid catastrophic forgetting and enable scalable learning.

- **Key Steps:**
    - **Training Primitives:**
        - Begin with easier motion sequences.
        - Identify hard-to-imitate sequences (e.g., those with high failure rates).
        - Add new primitives (subnetworks) to specialize on harder subsets.
  - **Freezing Older Primitives:** Preserve prior capabilities by freezing older primitives during new task learning
  - **Composer Network:** Combines outputs of all primitives, dynamically selecting the best primitive for the current task.

#### 3. Fail-State Recovery

- **Objective:** Recover from failure states (e.g., fallen humanoids, far-away initializations) and resume tracking reference motion.

- **Approach:**
    - Modify input states to focus on root positions rather than full-body reference.
    - Train fail-recovery primitive using walking/running sequences to bias toward simple locomotion.
    - Incorporate transition mechanisms to switch back to full-motion tracking once close to reference motion.

- **Training:**
    - Randomly drop the humanoid in various fail conditions.
    - Apply additional penalties and rewards for successful recovery and energy efficiency.

#### 4. Data and Training Setup

- **Datasets:**
    - **AMASS Dataset:** Preprocessed to remove noisy or object-interaction-based sequences.
    - **H36M Dataset:** Used for testing unseen motion sequences.

- **Preprocessing:**
    - Normalize sequences using forward kinematics.
    - Apply relaxed early termination to allow slight deviations for balance.

- **Training Process:**
    - Use PPO (Proximal Policy Optimization) for reinforcement learning.
    - Employ parallel simulations (e.g., using Isaac Gym) for large-scale training.
    - Incorporate a Gaussian filter for smoothing noisy reference motion.

#### 5. Real-Time Simulated Avatars

- **Video-Driven Motion:**
    - Use pose estimators like **HybrIK** and **MeTRAbs** to extract joint rotations and 3D keypoints from video streams.
    - Integrate the estimations with the humanoid controller for real-time avatar simulations.

- **Language-Driven Motion:**
    - Use motion generation models like **MDM (Motion Diffusion Model)** to produce reference keypoints from textual prompts.
    - Seamlessly blend disjoint motion clips via the fail-state recovery capability.

### Implementation Steps

#### Step 1: Setup Simulation Environment
- Select or construct humanoid models using SMPL kinematic structure.
- Implement PD control for actuation at each joint.

#### Step 2: Train Initial Primitive
- Train on the easiest subset of motion sequences from AMASS using imitation rewards.

#### Step 3: Incrementally Add Primitives
- Identify hard sequences and train new primitives using lateral connections or weight-sharing mechanisms.
- Freeze parameters of previously trained primitives.

#### Step 4: Train Fail-Recovery Primitive
- Use random initialization of fail states.
- Design rewards to prioritize reaching the reference position naturally.

#### Step 5: Integrate Composer
- Train the composer network to dynamically combine primitives for generalized motion imitation.

#### Step 6: Real-Time Integration
- Use off-the-shelf pose estimators or motion generators to provide reference motions.
- Smooth the input using temporal filters.

#### Step 7: Testing and Evaluation
- Evaluate the controller on unseen datasets (e.g., H36M) and noisy inputs.
- Measure success rates, physical fidelity, and recovery performance.

### Key Deliverables

- **Trained Controller:** A composite policy integrating primitives and fail-recovery mechanisms.
- **Simulation Setup:** A pipeline to execute and render real-time simulations using keypoint or rotation-based input.
- **Evaluation Framework:** Quantitative metrics (e.g., success rate, MPJPE) and qualitative demos.
